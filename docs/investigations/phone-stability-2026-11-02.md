# Android stability investigation

Base: e2abd2e, branch fix/phone-stability. Evidence is read-only in the owner's .audit/phone-logs-2026-11-02 directory. No device access.

## Root causes, before implementation

1. `AndroidLibrespotPlaybackHost.kt:245` creates the unpatched librespot-android 0.2.0 Session. Artifact bytecode confirms Session.reconnect invokes Receiver.stop then ApResolver.refreshPool. Receiver.stop unconditionally interrupts its thread, including itself. Reconnect catches IOException, GeneralSecurityException and SpotifyAuthenticationException, but not InterruptedException escaping the HTTP implementation. logcat.txt:99738-99766 proves that exact fatal path at 17:24:17.488; all.log:19940 records the receiver crash. No host shutdown is needed to trigger it. A narrowly scoped per-receiver guard installed by the public reconnection listener is necessary because the library owns thread creation and exposes no thread factory. It recognizes only InterruptedException at ApResolver.request under Session.reconnect. Recovery closes/recreates the exact failed session under the host mutex; shutdown/replacement wins by identity. It pauses transport without autoplay. Existing R8 rules preserve the matched library class/method names.

2. `AndroidPlaybackService.kt:38` has no foreground denial listener. More importantly Media3 1.8.0 MediaNotificationManager.java:271-276 asynchronously calls updateNotificationInternal after artwork loads; startForeground at :461 calls ContextCompat.startForegroundService outside MediaSessionService's synchronous exception catch. logcat.txt:2-31 records the main-thread fatal at 09:21:40.432. The supplied all.log begins at 14:49:19, and logcat starts with the morning fatal, so neither preserves the playback initiator at 09:21. Desktop remote, handoff, media button and resumption cannot honestly be distinguished from this evidence. Fix both synchronous denial via the documented listener and asynchronous notification callback denial at the provider boundary. Pause PlayerSession and tell the user to reopen the app and press Play.

3. `AndroidLibrespotPlaybackHost.kt:313-322` deduplicates identical booleans but forwards every alternating halt as BUFFERING/PLAYING. `AndroidPlaybackEngine.kt:334-340` publishes each with a new position; PlayerSession.kt:160 logs each publication. Add a short persistent-halt delay and status deduplication at the receiver event boundary; terminal/seek/track changes bypass/reset the filter.
