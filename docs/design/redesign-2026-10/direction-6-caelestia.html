Caelestia

On Linux the Kainos window stops bringing its own skin and wears the shell's: the same corner radii, the same Google Sans Flex scale, 85% surfaces over the wallpaper blur, the tonal buttons that square off when they are on, and the shell's wavy seek bar, so Kainos beside the Caelestia dashboard reads as one system. None of the colours are Kainos's own. Every surface and control is a Material 3 role read from ~/.local/state/caelestia/scheme.json, so when the wallpaper changes, the player changes with it. Pick a scheme in the top-left corner: the page, the shell and the window re-theme together.

How it works, for later

Read and watch. On start the desktop app reads ~/.local/state/caelestia/scheme.json and watches its directory with a WatchService; Caelestia rewrites the file on every wallpaper or scheme change (caelestia scheme set, caelestia wallpaper). Debounce ~150 ms and re-read, since the file is replaced, not appended. The transition is a 300 ms colour cross-fade, the same CAnim the shell uses.

Map 1:1. The file's colours keys are the M3 role names; they map straight onto a Compose ColorScheme: background, surface, surfaceDim and surfaceBright, the five surfaceContainer tones, onSurface and onSurfaceVariant, outline and outlineVariant, inverseSurface, inverseOnSurface, inversePrimary, primary / secondary / tertiary with their on- and container pairs, the error set, scrim, and surfaceTint = primary. mode decides light or dark, so the Light / Dark / System control is disabled while following.

Fall back. If the file is missing, malformed, or lacks a role, use the Kainos scheme chosen underneath. Today's Olive Grove and Caelestia Teal are frozen copies of this same file and can retire once the live mapping ships. Settings → Appearance shows the option only when the file exists; on Android and on desktops without Caelestia the page is unchanged.

Transparent window, separate item. The window stays opaque by default and still matches, since Caelestia's roles are opaque colours too. The 85% translucent, undecorated window over Hyprland blur shown here is optional: Compose Desktop can make an undecorated window with per-pixel alpha, but on Wayland it means an xdg-decoration none request, a windowrule blur plus ignore_alpha for the Kainos class, and a drag region of our own. Worth a spike after the colour mapping, not before.

Phone and PC togetherFolio on the phone, Caelestia on the PC, the same track

  • Shared: the information architecture. Home, Search, Library and Settings in the same order, Now Playing over everything, the Queue beside it; the same names everywhere (Local files only, Favorites only, Play favorites, Sleep after this track, Discover Weekly, Follow Caelestia theme).
  • Shared: Now Playing's order and controls. Cover, title, artist, source and quality, seek, shuffle / previous / play / next / repeat, heart, sleep timer, queue. Shuffle has a clear on state on both; repeat shows off / all / one on both; the six availability states and the hearts-and-sync model underneath are identical.
  • Platform-specific: the skin. Folio's paper, serif, hairline ledgers and ruled seek scale on the phone; Caelestia's roles, Google Sans Flex, tonal buttons and wavy seek on the PC. Desktop keeps its mouse-and-keyboard extras (volume slider, Space to play / pause, type-to-search, compact player).
  • Platform-specific: where the colours come from. The phone's tint picker and the PC's live scheme are separate choices; they only agree when you pick similar hues. Album light is an ink wash on the phone and a glow inside the cover card on the PC.
  • The honest cost. Two Compose themes and two sets of component styles to keep in step. The shared presenters and screen composables do not change, but every shared composable must take colour, shape and type from the theme only, which is the same discipline the live Caelestia mapping needs anyway.
